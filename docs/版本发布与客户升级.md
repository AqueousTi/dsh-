# 版本发布与客户升级：准备方案

先发布经过新机验证的源码版本，记录DSH/AstrBot/Windows兼容范围；Release提供更新说明和校验值。
不把1.74GiB完整包直接提交进Git历史，不把运行后的目录当作发行母包。
完整包/依赖仅在有相应分发权限时发布，源码公开不自动意味着全部附件获准公开或商用。

第一阶段采用人工下载升级包，明确可从哪些旧版本升级。更新应停止对应进程、备份与校验、
保留客户配置/记忆/自定义角色/账号数据，失败回退。不要让客户通过pip盲目升级锁定AstrBot。
之后再实现Bot“检查更新”和独立更新器；当前源码没有自动更新功能。

视频先演示真实干净系统安装与一次实际回复，遮住Key、密码、二维码及客户信息。
远程服务需写清交付内容、验收方法、维护范围与期限；发布收费服务前核实所用项目授权和平台类目规则。
